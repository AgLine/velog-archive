# 운영체제 기본 개념

### 운영체제의 주요 역할 4가지는?

- 프로세스 관리: CPU 스케줄링, 프로세스 생성/종료
- 메모리 관리: 메모리 할당/회수, 가상 메모리
- 파일 시스템 관리: 파일 저장, 접근 제어
- 입출력 관리: 장치 드라이버, I/O 스케줄링

### 프로세스(Process)와 스레드(Thread)의 차이는?

|  | 프로세스  | 스레드  |
| --- | --- | --- |
| 정의  | 실행 중인 프로그램 | 프로세스 내 실행 단위 |
| 메모리  | 독립적  | 공유 (코드, 데이터, 힙) |
| 생성 비용 | 높음 | 낮음  |
| 통신  | IPC 필요 | 직접 통신 가능 |
| 안정성  | 높음 (독립적) | 낮음 (상호 영향) |

### 프로세스의 상태 전이도를 그리고 설명하시오.

```java

생성(new) → 준비(ready) → 실행(running) → 종료(terminated)
              ↑   ↓           ↓
              ←───────────────
             (timeout)     대기(waiting)
                              ↑   ↓
                            I/O 완료
```

- 생성: 프로세스 생성
- 준비: CPU 할당 대기
- 실행: CPU에서 실행 중
- 대기: I/O 등 이벤트 대기
- 종료: 실행 완료

### **PCB(Process Control Block)에 저장되는 정보는?**

- 프로세스 ID (PID)
- 프로세스 상태
- 프로그램 카운터 (PC)
- CPU 레지스터 값
- 메모리 관리 정보
- 스케줄링 정보
- I/O 상태 정보

### **컨텍스트 스위칭(Context Switching)이란?**

- CPU가 한 프로세스에서 다른 프로세스로 전환
- 과정:
    1. 현재 프로세스 상태를 PCB에 저장
    2. 다음 프로세스의 PCB를 복원
    3. 새 프로세스 실행
- 오버헤드 발생 (순수 낭비 시간)

### **CPU 스케줄링 알고리즘 5가지를 설명하시오.**

- FCFS (First Come First Served): 도착 순서대로, 비선점
- SJF (Shortest Job First): 실행시간 짧은 것 먼저, 평균 대기시간 최소
- SRT (Shortest Remaining Time): SJF의 선점형
- Priority: 우선순위 높은 것 먼저, 기아 문제 가능
- Round Robin: 시간 할당량(quantum)씩 순환, 시분할

### **교착상태(Deadlock)의 4가지 필요조건은?**

1. 상호배제(Mutual Exclusion): 자원을 한 번에 하나만 사용
2. 점유와 대기(Hold and Wait): 자원 보유하며 다른 자원 대기
3. 비선점(No Preemption): 강제로 자원 빼앗기 불가
4. 순환대기(Circular Wait): 자원 대기가 순환 구조

### **교착상태 해결 방법 4가지는?**

- 예방(Prevention): 4가지 조건 중 하나를 부정
- 회피(Avoidance): 안전 상태 유지 (Banker's Algorithm)
- 탐지 및 회복(Detection & Recovery): 발생 후 처리
- 무시: 발생 확률 낮으면 무시 (Ostrich Algorithm)

### **메모리 관리 기법 중 페이징(Paging)을 설명하시오.**

- 물리 메모리를 고정 크기(프레임)로 분할
- 논리 메모리를 같은 크기(페이지)로 분할
- 외부 단편화 해결, 내부 단편화 발생
- 페이지 테이블로 주소 변환
- 일반적으로 4KB 크기 사용

### **가상 메모리(Virtual Memory)란?**

- 물리 메모리보다 큰 프로그램 실행 가능
- 디스크를 메모리처럼 사용 (스왑 영역)
- 프로세스마다 독립적인 주소 공간
- 페이지 폴트(Page Fault) 발생시 디스크에서 로드
- 장점: 다중 프로그래밍, 메모리 효율성

### **페이지 교체 알고리즘 4가지는?**

- FIFO: 먼저 들어온 페이지 교체, Belady's Anomaly 발생
- LRU (Least Recently Used): 가장 오래 사용 안 한 페이지
- LFU (Least Frequently Used): 사용 빈도 가장 낮은 페이지
- Optimal: 앞으로 가장 오래 사용 안 할 페이지 (이상적)

### **Thrashing(스래싱)이란?**

- 페이지 폴트가 과도하게 발생하는 현상
- 프로세스가 실행보다 페이징에 더 많은 시간 소비
- 원인: 다중 프로그래밍 정도가 과도하게 높음
- 해결: 프로세스 수 줄이기, 메모리 증설, Working Set 관리

### **캐시 메모리의 지역성(Locality) 원리는?**

- 시간적 지역성(Temporal): 최근 참조된 데이터는 곧 다시 참조됨
    - 예: 반복문의 변수
- 공간적 지역성(Spatial): 참조된 주소 근처가 곧 참조됨
    - 예: 순차적 배열 접근

### **인터럽트(Interrupt)와 폴링(Polling)의 차이는?**

- 인터럽트: 이벤트 발생시 CPU에 신호, 비동기적
    - 장점: 효율적, 빠른 응답
    - 단점: 구현 복잡
- 폴링: CPU가 주기적으로 상태 확인, 동기적
    - 장점: 구현 간단
    - 단점: CPU 낭비

### **동기(Synchronous)와 비동기(Asynchronous)의 차이는?**

- 동기: 작업 완료까지 대기, 순차적 실행
    - 예: 함수 호출 후 반환까지 대기
- 비동기: 작업 완료를 기다리지 않음, 병렬적
    - 예: AJAX 요청, 콜백 함수

### 파일 권한 숫자의 의미는?

```bash
r(읽기) = 4
w(쓰기) = 2
x(실행) = 1

755 = rwxr-xr-x
- 7 = 4+2+1 = rwx (소유자)
- 5 = 4+0+1 = r-x (그룹)
- 5 = 4+0+1 = r-x (기타)

644 = rw-r--r--
- 6 = 4+2 = rw- (소유자)
- 4 = 4 = r-- (그룹)
- 4 = 4 = r-- (기타)
```

# 운영체제 고급 개념

### **임계 영역(Critical Section) 문제와 해결 조건은?**

- 임계 영역: 공유 자원 접근 코드 부분
- 해결 조건:
    1. 상호 배제: 한 번에 하나만 진입
    2. 진행: 선택은 유한 시간 내
    3. 한정 대기: 무한 대기 방지

### **세마포어(Semaphore)와 뮤텍스(Mutex)의 차이는?**

| 구분 | 세마포어 | 뮤텍스 |
| --- | --- | --- |
| 카운트 | N개 가능 | 0 또는 1 |
| 소유권 | 없음 | 있음 (락 획득자만 해제) |
| 용도 | 동기화, 자원 수 제한 | 상호 배제 |

```java
// 세마포어
Semaphore sem = new Semaphore(3);  // 3개 허용
sem.acquire();
// critical section
sem.release();

// 뮤텍스
ReentrantLock lock = new ReentrantLock();
lock.lock();
// critical section
lock.unlock();
```

### **모니터(Monitor)란?**

- 공유 자원과 접근 메서드를 하나로 묶은 객체
- 한 번에 하나의 스레드만 진입 가능
- 조건 변수(condition variable)로 대기/신호
- Java의 synchronized가 모니터 구현

### **세그멘테이션(Segmentation)이란?**

- 논리적 단위(세그먼트)로 메모리 분할
- 세그먼트: 코드, 데이터, 스택, 힙 등
- 가변 크기, 외부 단편화 발생
- 세그먼트 테이블로 주소 변환

### **내부 단편화와 외부 단편화의 차이는?**

- 내부 단편화: 할당된 메모리 내부의 낭비
    - 페이징에서 발생
    - 예: 4KB 페이지에 1KB만 사용
- 외부 단편화: 할당 가능하지만 분산된 메모리
    - 세그멘테이션에서 발생
    - 압축(compaction)으로 해결

### **DMA(Direct Memory Access)란?**

- CPU 개입 없이 I/O 장치가 메모리에 직접 접근
- CPU는 다른 작업 수행 가능
- I/O 완료시 인터럽트로 CPU에 알림
- 대용량 데이터 전송에 효율적

### **시스템 콜(System Call)이란?**

- 사용자 프로그램이 운영체제 서비스를 요청
- 커널 모드로 전환하여 실행
- 종류:
    - 프로세스 제어: fork(), exec(), exit()
    - 파일 관리: open(), read(), write()
    - 장치 관리: ioctl()
    - 정보 유지: getpid(), alarm()
    - 통신: pipe(), socket()

### **IPC(Inter-Process Communication) 방법은?**

- 파이프(Pipe): 단방향 통신
- 메시지 큐(Message Queue): 메시지 단위 전송
- 공유 메모리(Shared Memory): 가장 빠름, 동기화 필요
- 소켓(Socket): 네트워크 통신 가능
- 시그널(Signal): 비동기 이벤트 통지

### **RAID의 종류와 특징은?**

- RAID 0: 스트라이핑, 성능 향상, 안정성 없음
- RAID 1: 미러링, 안정성 향상, 용량 50%
- RAID 5: 패리티, 성능+안정성, 최소 3개 디스크
- RAID 6: 이중 패리티, RAID 5보다 안전
- RAID 10: RAID 1+0, 미러링+스트라이핑

### **파일 시스템의 종류와 특징은?**

- FAT32: 호환성 좋음, 4GB 파일 제한
- NTFS: Windows 기본, 큰 파일 지원, 권한 관리
- ext4: Linux 기본, 저널링, 큰 파일 지원
- XFS: 대용량 파일, 고성능
- Btrfs: 스냅샷, 압축, 최신 Linux

### **저널링(Journaling) 파일 시스템이란?**

- 파일 시스템 변경 사항을 로그(저널)에 먼저 기록
- 시스템 crash 후 빠른 복구 가능
- 메타데이터 또는 데이터+메타데이터 저널링
- ext3, ext4, NTFS 등이 지원

### **inode란?**

- Unix/Linux 파일 시스템의 파일 정보 구조체
- 포함 정보:
    - 파일 타입, 권한
    - 소유자, 그룹
    - 파일 크기
    - 타임스탬프
    - 데이터 블록 포인터
- 파일 이름은 디렉토리에 저장

### **하드 링크와 심볼릭 링크의 차이는?**

| 구분 | 하드 링크 | 심볼릭 링크 |
| --- | --- | --- |
| 동작 | 같은 inode 공유 | 경로만 저장 |
| 원본 삭제 | 영향 없음 | 링크 깨짐 |
| 디렉토리 | 불가 | 가능 |
| 파일시스템 | 같아야 함 | 달라도 됨 |

```bash
ln file hardlink       # 하드 링크
ln -s file symlink     # 심볼릭 링크
```

### **cron과 at의 차이는?**

```bash
# cron: 주기적 작업 스케줄링
crontab -e             # 편집
# 분 시 일 월 요일 명령
0 2 * * * /backup.sh   # 매일 2시

# at: 일회성 작업
at 10:00 PM tomorrow
at> /backup.sh
at> <Ctrl+D>

atq                    # 대기 작업 확인
atrm job_number        # 작업 삭제
```

### SELinux와 AppArmor란?

- SELinux (Security-Enhanced Linux):
    - 강제 접근 제어(MAC) 시스템
    - Red Hat, CentOS 기본
    - 복잡하지만 강력한 보안
    - 모드: Enforcing, Permissive, Disabled
- AppArmor:
    - 경로 기반 MAC
    - Ubuntu, Debian 기본
    - 상대적으로 쉬움
