# 도커(Docker)란 무엇인가?

게시일: 2026-01-22T08:19:13.636Z
시리즈: Docker

---

도커를 사용은 해봤지만 막상 면접에서 "도커가 뭔가요" 라고 물었을 때 
서로 다른 개발환경을 통일하기 위한 도구? 라는 식으로 두루뭉실하게 말해버렸다....

다음에는 자신있게 답하기 위해 정리해보려함

# 1. 왜 도커가 등장했나?
**"내 컴퓨터에선 되는데 왜 네 컴퓨터에선 안 되지?"**

**문제 상황** : 
- 로컬 개발 환경(Mac/Windows)과 서버 환경(Linux)이 달라서 생기는 오류, 라이브러리 버전 충돌 등.

- 과거에는 서버에 프로그램을 배포하려면 OS 깔고, 자바 버전 맞추고, 환경 변수 설정하고... 복잡했음.

- 개발 서버와 운영 서버의 환경이 조금만 달라도 에러발생.

**해결책**
- 소프트웨어를 실행하는 데 필요한 모든 환경(코드, 라이브러리, 설정 파일 등)을 하나로 포장해서 배포하자! -> 컨테이너의 개념 탄생.

# 2. 도커의 정의
**"도커는 컨테이너 기반의 오픈소스 가상화 플랫폼"** 
애플리케이션을 실행하는 데 필요한 모든 환경(코드, 라이브러리, 설정 파일 등)을 하나로 묶어 어디서든 동일하게 실행되도록 해주는 도구.

# 3. 도커의 구성
### 1. Dockerfile
- 도커 이미지를 만들기 위한 설계도
```
# 1. Base Image: 무엇을 기반으로 할 것인가?
# (사용자가 Java 17을 쓰므로 openjdk 17 버전을 가져옵니다)
FROM openjdk:17-jdk

# 2. Work Directory: 컨테이너 내부의 작업 공간 설정
# (컨테이너 안에서 /app 폴더를 만들어 거기서 작업하겠다는 뜻)
WORKDIR /app

# 3. Copy Files: 내 컴퓨터의 파일을 컨테이너 안으로 복사
# (빌드된 jar 파일을 컨테이너 내부의 app.jar라는 이름으로 복사)
# *주의: 미리 ./gradlew build로 jar 파일을 만들어둬야 함
COPY build/libs/*.jar app.jar

# 4. Expose Port: 컨테이너가 사용할 포트 명시
# (스프링 부트 기본 포트인 8080을 열어둠)
EXPOSE 8080

# 5. Entrypoint: 컨테이너가 시작될 때 실행할 명령어
# (java -jar app.jar 명령어를 실행함)
ENTRYPOINT ["java", "-jar", "app.jar"]
```

### 2. Image
- Dockerfile을 빌드해서 만들어진 **실행 파일(프로그램)**
- **불변(Immutable)**의 상태로, 읽기 전용

### 3. Container
- 이미지를 실행하여 메모리에 올라간 **프로세스(인스턴스)**
- 이미지를 기반으로 생성된 독립적이고 격리된 실행 환경을 의미
- 이미지 하나로 여러 개의 컨테이너를 띄울 수 있음

# 4. 도커(Docker)와 VM(Virtual Machine)의 차이점
**Docker**

- 호스트 운영 체제 위에 실행하는 것으로 컨테이너라는 단위로 애플리케이션과 필요한 라이브러리 및 종속성을 패키징
- Docker 컨테이너는 ‘호스트 커널’을 공유하므로 가볍고 빠르게 실행될 수 있음
- 여러 컨테이너를 실행하는 경우 각 컨테이너는 격리되지만 공유 리소스를 사용하여 높은 효율성을 유지

**VM(Virtual Machine)**

- 호스트 컴퓨터 위에 가상 운영 체제를 실행하는것으로 각 운영 체제는 자체 커널을 가지고 독립적으로 작동
- 이는 각 VM이 완전히 격리되어 있고 서로 영향을 주지 않는다는 이점이 있음. 하지만 VM은 용량과 성능 측면에서 무겁고 비교적 오버헤드가 많이 발생할 수 있음



**가상화의 목적이 완전한 격리와 다양한 운영 체제의 실행이라면 VM**

**애플리케이션의 패키징, 배포, 확장에 초점을 둔다면 Docker**

# 5. 도커를 사용했을 때 장점
- **일관된 환경** : 개발, 테스트, 운영 환경을 동일하게 유지하여 "내 컴퓨터에서는 되는데..." 문제를 해결합니다.
- **빠른 배포 및 실행** : 컨테이너는 운영체제 부팅 없이 즉시 실행되므로 배포 시간이 매우 빠르고, 가벼워 신속한 확장이 가능합니다.
- **격리 및 독립성** : 각 컨테이너는 독립된 환경에서 실행되어 서로 영향을 주지 않으며, 애플리케이션의 독립성을 보장합니다.
- **리소스 효율성** : 호스트 OS의 커널을 공유 사용하므로 가상 머신(VM)보다 훨씬 가볍고, 하나의 물리 서버에 더 많은 컨테이너를 실행할 수 있어 리소스 활용률을 높입니다.
- **이식성** : 컨테이너 이미지는 어떤 환경(로컬, 클라우드, 온프레미스)에서든 동일하게 실행되므로 이식성이 매우 뛰어납니다.
- **표준화 및 재현성** : 애플리케이션 배포 및 실행 과정을 표준화하고 자동화하여 운영을 용이하게 합니다.
- **마이크로서비스 아키텍처 지원** : 여러 개의 작은 서비스(컨테이너)로 나누어 개발 및 배포하는 마이크로서비스에 이상적입니다.
- **DevOps 및 CI/CD 효율 증대** : 개발 파이프라인(CI/CD)에 통합되어 자동화된 빌드, 테스트, 배포를 가능하게 합니다.
# 결론
Q . 도커가 뭔가요?

A . 도커는 애플리케이션 실행 환경을 컨테이너로 추상화하여 어떤 환경에서든 동일하게 실행되도록 보장해주는 플랫폼입니다. 가상 머신(VM)처럼 OS 전체를 설치하는 게 아니라 OS 커널을 공유하며 프로세스 단위로 격리하기 때문에 가볍고 빠르다는 장점이 있습니다.
